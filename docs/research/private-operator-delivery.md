# Private research operators

The Windows kit builds `aegis-client`/`aegis-winctl` with the declared Chrome-like TLS/QUIC features, then builds the optional research operators in a separate Cargo invocation with no default features and the `none` operator build identity. An operator identity must not mask the client's transport provenance. Separate invocations also give the operators a distinct dependency feature union; they do not borrow the client's Chrome-like features. The build helper restores the caller's feature environment after success, nonzero exit or command failure. Client version, research metadata, source/lock drift and private package checks remain mandatory; sentinel tests of this helper do not accept an actual executable or signed release.

The producer mapping is explicit on Linux and Windows: build `aegis-research-measure` (or `aegis-research-measure.exe`), then copy it to the delivered `aegis-measure` leaf. Missing restricted output refuses staging even if the normal full tool exists. The normal `aegis-measure` build tool remains the default Cargo target for validators and dependency notices and refuses `research-build-info` rather than claiming an exclusive seven-action surface. The restricted executable shares the existing seven implementations and registers only `private-control`, `poisson-control`, `poisson-insertion`, `privacy-pcap-export`, `privacy-study-assemble`, `privacy-frontier` and `brain-outcome-replay`, plus build-info/help/version entrypoints. Renaming a full tool, setting an environment flag or trusting metadata is not a substitute for this executable role.

The Linux builder creates two private archives. The existing `aegis-VERSION-linux-ARCH.tar.gz` is an administrative operator archive: it retains the full normal `bin/aegis-measure`, the original 32 helper scripts, client/server and their existing installation material. Those helpers need real administrative selectors, including TPROXY startup fields, runtime event summaries and evidence writing. This archive has no claim of an exclusive seven-action research surface. Installing the client or helper does not itself install the measure tool; existing administrative executable selection still requires the operator's trusted explicit path.

The separate `aegis-research-VERSION-linux-ARCH.tar.gz` contains only prebuilt restricted `bin/aegis-measure`, `bin/aegis-transport-lab`, their bound research guide/capture set, `research.manifest.json` and `SHA256SUMS`. The entire tree and archive members are admitted against that exact inventory; administrative tools, installer/helper material and extra payload leaves refuse. This research payload does not activate a service, install a traffic schedule, enroll a device or supply credentials. No source checkout or Cargo is required on the recipient.

The Linux archive includes the bounded guide set listed in `packaging/research-operator-guides.txt`, copied as regular files into `research/`. Start with [research components and composition](implementation-and-composition.md); its local guide links and their dependencies resolve within that directory without a checkout. `README.md` is an alias of this delivery guide. The archive admission requires and hashes each guide and rejects unexpected research payload files. The guide set contains instructions and scope statements, never source trees, evidence, operator profiles or credentials. The separate Windows research output uses the same bound guides; the mixed Windows engineering kit keeps its existing inventory and help entrypoints.

The existing private Linux release manifest binds the separate research archive hash, checksum sidecar and inner manifest hash. The existing detached signature on that parent manifest covers these typed references; verify the parent signature, exact source and referenced archive/member hashes before use. No new signing key, credential or public asset is introduced. The administrative bundle remains a separate artifact in that same private parent delivery. Build-info is bounded producer metadata and actual executable hashes, not independent reproduction or a cryptographic proof of compiler behaviour. Tool crate versions (currently measure0.3.12/lab0.1.0) are separate from the product release version. Source, Cargo.lock, target, compiler and exact executable identities must agree. The generic Linux ABI gate includes each tool separately without substituting it for the client/server.

`bin/aegis-measure research-build-info` and `bin/aegis-transport-lab --build-info` display public executable provenance. `bin/aegis-measure --help` and the two documented `poisson-control --help` / `poisson-insertion --help` commands display the existing bounded SDK interfaces. Private configuration, keys, leases and application/control input files are independently supplied by the authorized operator, never included in this payload. The Poisson operators use explicit application-owned source/sink custody, fail-closed clocks/counts and genuine paired authentication. They do not borrow arbitrary browser, operating-system or full-wide traffic and do not establish a legitimate Poisson process, M/M/1 service, a whole-wire cover law or a DPI field result.

`bin/aegis-transport-lab --help` describes finite offline analysis for dependency/topology, AWGN, Poisson, privacy-channel and BIT-TRAPS inputs. The delivered CLI registers those six existing capabilities and omits the undeclared offline `demo` entrypoint. Its underlying library demonstration APIs and original numerical scope remain unchanged. A model report is not installed protection or a field measurement. The private PCAP→study→frontier and bandit replay commands on `aegis-measure` likewise preserve their original empirical scope.

Both tools are deliberately excluded from the public client archive and mirrors. Their delivery neither enables all research owners together nor accepts an installed release/full-wide lifecycle or beta exit. With `-IncludeResearchOperators`, the Windows builder retains the mixed engineering kit and also writes a separate `KIT.research.zip` sibling containing the restricted pair and admitted guide tree. Both the inner manifest and the sibling archive/member hashes are checked; the delivery record labels this output `private_research_only`, `signed_release=false`. This additional unsigned output is not admitted by the existing Authenticode finalizer as a signed research release. The existing kit schemas, client provenance and signing-policy checks remain mandatory; six unprovisioned production Authenticode inputs remain blockers. Neither source admission, copied executable inventory nor a controlled local command test establishes native installation, wire privacy or field acceptance.
