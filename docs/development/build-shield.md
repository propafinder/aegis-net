# Сборка с Aegis-Shield (LLVM / обфускация)

Полная **Control Flow Flattening** и прочие LLVM-pass **не входят** в обычный `cargo build`: это отдельный этап CI или локальный `clang` + проприетарные плагины.

Важно:
- это документ про **optional release-hardening path**, а не про текущий обязательный build/runtime baseline проекта
- наличие `shield/*` в репозитории не означает, что полный LLVM/encrypted-Lua target-state уже реализован в open-source runtime

## Рекомендуемый контур

1. Соберите артефакт `cargo build --release` без обфускации (воспроизводимость, отладка).
2. Пропустите бинарник через выбранный LLVM obfuscator (или коммерческий пайплайн), **сохраняя** совместимость с целевой glibc/macOS.
3. Подпишите выпуск (codesign / gpg) отдельно от разработки.

## Переменные окружения (runtime Shield)

| Переменная | Назначение |
|------------|------------|
| `AEGIS_SHIELD=0` | Пропустить sentinel только в debug-сборке; release-сборка игнорирует обход, пишет предупреждение и продолжает проверку |
| `AEGIS_STATE_KEY` | 64 hex — ключ шифрования файла состояния |
| `AEGIS_STRING_KEY` / `AEGIS_ENCRYPTED_BLOB` | XOR-раскодировка вспомогательных данных |
| `AEGIS_OPAQUE_SECRET` | Секрет для расширения 0xFAC7 в ClientHello |

Текущий клиент вызывает sentinel с `exit_if_debugger = false`: обнаружение
отладчика или VM лишь предупреждает в журнале. Название `sleep_if_vm` не
означает, что этот путь задерживает работу. Сам API умеет завершать процесс,
если другой вызывающий код явно передаст `exit_if_debugger = true`; это не
поведение текущего клиента. Sentinel не защищает от администратора, локального
вредоносного процесса или копии диска. XOR-раскодировка строк — обфускация,
а не криптографическое шифрование или защита ключей.

## Lua

Сборка с интерпретатором: `cargo build -p aegis-core --features lua` и при необходимости `-p aegis-client --features lua` (пробросьте feature в `aegis-client/Cargo.toml`).
