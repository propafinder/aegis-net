# Client packet engine library extraction

The client library owns the existing dual-stack smoltcp loop formerly in `ingress/wide/ip_tunnel.rs`, its actual two-worker Tokio runtime, packet queue bounds, flow limits, MTU checks, UDP generation matching, fragmentation and lossless TCP pump. `PacketIo` and `TunnelStats` are the original contract and counters, with the Wintun implementation owned by the library to obey Rust orphan rules. No dependency or manifest change is proposed.

`run_ready_with_services` takes the existing `RelaySettings`, an explicit `Arc<dyn RelayServices>`, the existing shared stop flag, limits and callback. The callback still means engine construction, not authenticated admission. The synchronous caller owns the engine thread; setting the stop flag ends the loop, drops UDP jobs/runtime, and returns its actual result. Thread cancellation/join belongs to that caller. This seam grants no credentials or transport authority.

The binary facade preserves the existing run/run_ready call sites and original native test modules. Its concrete `ClientRelayServices` calls the existing TCP relay with the same three optional `None` inputs (initial payload, mimicry context, outcome sink), existing UDP datagram/flow relay, and original six runtime event codes. All transport eligibility, secure retry, endpoint selection, TLS and certificate checks remain in that actual relay implementation. No transport code is copied or replaced. The exact SOCKS target/packet types and stateless error helpers move to library source; binary imports preserve all original parser/authentication tests.

The fake-IP allocator/parser has one shared source body included by the original binary DNS owner and by the packet library. It creates only explicitly owned map instances, with no global map. Linux DNS socket/listener ownership remains in the binary. TCP and UDP asynchronous tasks retain their existing FakeIpLease for their entire future; unknown synthetic destinations still fail rather than use numeric fallback. The original private Phy device body is likewise shared with the unchanged native fixtures. The original binary DNS test body is preserved. Library `cfg(test)` tracing belongs to library tests; a binary test does not enable diagnostic-only library `cfg(test)` output. Assertions, payload sizes and deadlines are unchanged.

The 62-file coherent source was adopted into the local checkout after exact source and preimage checks. Before adoption, that same pinned source passed strict, all-target Linux x86_64 cross-compilation with no Rust methods executed, and all 89 native Darwin client-library tests passed. The final canonical source passed a separate strict Linux cross-check with zero methods and a Darwin all-features library retry with 89/89 methods. The source and result receipts are under `evidence-archive/testing/2026-10-12/AUTO21-engine-relay-owners-*` and `client-final-Darwin-allfeatures-lib-r2/`. These checks do not establish an installed Linux client or an authenticated macOS tunnel. The NetworkExtension package now has an opt-in `PacketIo` adapter to the actual shared engine; its canonical native source checks and 16/16 library methods passed. It has no registered session factory, relay/credential/ACK owner or admitted provider session, so normal start still refuses before network settings. Containing-app signing, installation, profiles, keychain admission, activation and traffic acceptance remain separate.

## Next concrete owner extraction

The next increment must supply a real provider-side relay service using the existing relay implementation and its dependencies, rather than a copied transport or unconstrained factory flag. Actual event, Brain, mimicry, ECH-policy and credential-path owners are already shared with the library. Owners still outside it include `relay.rs` and its secure/endpoint/carrier modules, `device_bundle_online.rs`, `device_identity_store.rs`, `device_renewal.rs`, profile Geneva runtime authorization and ingress UDP control. Binary test-only relay injectors must retain their original test ownership.

The admitted session boundary already exists in `macos_tunnel/worker_runtime.rs`: checked_online, PreparedIdentity prepare/confirm, renewal Supervisor failure handling, live permission/ACK fingerprint + issued_generation + snapshot/profile rechecks and PacketGate expiry. Extract that ownership only with a typed captured session and a lifetime-bound cancellation owner. It must retain trust/identity/renewal, acknowledged policy generation, failure propagation and no post-authentication restart/replay. Secure retries remain limited to existing explicit pre-authentication DialFailure/CarrierUnavailable paths.

AppGroup custody for captured configuration, trust/certificate references and renewal ownership is a separate unfinished requirement; never store new credentials in source. Only after that owner exists can the NE adapter construct the real engine and register a factory. Signed packaging, approved activation and observed full IPv4/IPv6 DNS and fail-closed lifecycle acceptance remain separate subsequent work.
