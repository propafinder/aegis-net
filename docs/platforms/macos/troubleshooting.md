# macOS: troubleshooting

Symptoms seen on the installed client between v6 and v24, with the cause
found and the fix. Each row names the [B-06] entry of the
[change and incident log](../../../CHANGELOG.md) it
comes from. Commands use `H=/Applications/AEGIS.app/Contents/MacOS/aegis-ne-host`
and `P=dev.aegis.macos.PacketTunnel`.

Start with three read-only checks: `systemextensionsctl list`, `$H --ping`
and `$H --list`, then the provider log
([operate](operate.md#reading-the-provider-log)).

## Symptom, cause, fix

A build without it cannot be activated. |

| Activation exits 13 `replacement_declined`. | The bundle is not numerically newer than the active extension. | Build a new version; equal or older builds never replace the active extension. |
| Activation exits 2 and nothing was requested. | A wrong script option (`--activation-timeout`, removed; v6). | Use only the options in `install-app.sh --help`. |
| `$H --ping` reports `custody` EPERM on `private` and capture would refuse. | Pre-S13 providers walked from `/`; the sandboxed root provider cannot open ancestors above its container (v7). | Fixed since v8 (container-only anchor). Install a current build. |

Check the handoff expiry before a window. |
| Window checks fail for echo, whoami or TXT while the tunnel is Connected. | The relay's test services or window had expired (21 Oct, 22 Oct relay `relay-a` expiry). | Check the relay handoff's expiry time; ask the relay owner to extend it. |
| Connected, then `session_lost capture_lease_expired` within seconds, repeatedly. | PolicyAck round trips exceed the 3 s lease under the post-connect flow burst (v13-v22). | Fixed by pre-warmed, pipelined re-ACKs on a persistent ACK connection (v15-v23). Residual losses remain under load: see [known limits](known-limits.md#policyack-lease-of-3-s-under-load). |
| The 24 h certificate ran out. ## When asking for help

Collect, without key material or addresses:

- `systemextensionsctl list` (AEGIS lines), `$H --ping`, `$H --status`,
  `$H --list` (stdout and stderr), `$H --cert-status`;
- `log show --last 15m --style compact --predicate 'eventMessage BEGINSWITH "aegis-ne"'`;
- for a harness window, its `receipt.json` and `results.tsv`, redacted
  first (below).

The harness files are not all address-free. From the v34 harness the
real-relay window's `results.tsv` and `window.log` carry no address but the
tunnel's own fixed ones: the relay is written `relay_addr` and any other
address as its class (`ip4_global`, `ip6_ula`, ...), and every verdict is
still taken from the raw value. A window run with an earlier harness keeps
the first 80 bytes of the whoami reply in the `whoami_egress` row's detail,
on a pass and on a fail: on a pass that is the relay's address, and when
traffic left outside the tunnel it is the Mac's own public IPv4, the
address the tunnel is meant to hide; its `window.log` names the relay on
its first line. `receipt.json` holds the relay endpoint (the `relay`
field and the `relay_socket` check detail). Replace those values before
sharing, or share the files only privately with the relay owner.

Never send `identity/`, the invitation, a provisioning profile or a packet
capture.
