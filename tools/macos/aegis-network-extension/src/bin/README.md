# macOS native entrypoints

`host.rs` exposes explicit activation, saved-profile and connection controls. `provider.rs` registers the Packet Tunnel class and enters Apple's system-extension lifecycle. Building either binary does not run it.

Since B-06 S07 the provider registers the composite session factory before system-extension mode and applies tunnel network settings only after that session reports Ready under an authenticated PolicyAck lease. No provider binary has been executed, signed or installed from this source; installed tests remain outstanding. See the [package guide](../../README.md) and [module map](../README.md).

Since B-06 S10 the host also accepts bare `--ping` and `--status`, one bounded XPC exchange with the installed provider through the privileged bootstrap (exit 0 with one JSON line; 65 provider refusal or malformed reply; 69 service unavailable or signer refused; 75 no reply within 10 s). The four-argument `--status PROVIDER_ID OWNER_GENERATION RELAY_IP` remains the saved-profile VPN status. The provider starts its listener after system-extension mode. Neither binary has been run against the real system from this source.

Since B-06 S11 (source only; native behavior is proven in the attended installed run, S12) the host parses every verb in `host_lifecycle.rs` and refuses any other provider id:

- `--request-activation dev.aegis.macos.PacketTunnel` stops its run loop on the finish or failure callback, gives up after 120 s and prints one `activation_result=` line (with `will_complete_after_reboot`, `needs_user_approval` and `replacement_decision=none|replace|cancel`, the delegate's answer only: Apple acted on a `replace` only when `activation_result=completed` or `will_complete_after_reboot`). Exit 0 completed, 10 completes after reboot, 11 failed (including an unknown result value), 12 cancelled, 13 replacement declined, 14 timeout while approval was pending, 75 timeout, 2 usage. The replacement delegate returns Replace only for this provider and a numerically newer CFBundleVersion (`[1-9][0-9]{0,8}(\.(0|[1-9][0-9]{0,8})){0,2}`, padded to three parts); equal, lower, malformed or foreign versions Cancel.
- `--list` prints each saved profile of this provider with its `owner_generation` (only when printable), the scutil service id (the private `configuration.identifier` NSUUID, read only when both getters respond; else `unavailable`; S12 must cross-check `scutil --nc list`), typed-intent validity, enabled/on-demand and native status.
- `--remove-profile` calls removeFromPreferences on every saved profile of this provider, then reloads and exits 0 only when every one was removed and none remain.
- `--emergency-stop` calls stopVPNTunnel on every manager of this provider, not gated on an exact owner-generation/intent match, and warns when on-demand could restart it; a requested stop is not an observed disconnect.
- `--save-profile` prints `owner_generation=` on stdout on every outcome with `saved=true|false|unknown` (unknown once the save may be durable, expiry included). Profile verbs stay bounded at 30 s in all (since S16a one `Operation` deadline covers the provider terms query and the preference operation; the watchdog fires at that same deadline) and exit 2 on a preference refusal; a refused or unanswered terms query exits with the `--ping` codes (S16a, below).
- Each profile verb and bare `--ping`/`--status` prints exactly one result: the completion and its watchdog both claim a single `ResultClaim` before printing and exiting, so a completion racing the deadline never adds a second, contradictory `saved=`/`result=` line or exit code (the claim is unit-tested; the native wiring is proven only in S12).

Host `runtime.json` publication (`HostRuntimePublisher`) is unchanged: retiring it awaits an owner decision. Since S03 part 4 the provider never reads `runtime.json`; it derives its runtime binding from the held signed bundle, profile digest and Store issuance. Since S16a only the explicit `--repair-runtime` still calls it (its failure fails that verb alone); `--save-profile` no longer publishes.

Since B-06 S14 (source only) the host also accepts `--import-identity ABSOLUTE_AEGIS_DIR` and bare `--forget-identity`. The import reads `DIR/bundle` and `DIR/identity` into zeroizing buffers, sends them in one bounded XPC request and requires the provider's committed manifest to match what was sent; the provider requires the peer to be the console user and an admin, and refuses while a session is live. Exit codes are those of `--ping`, plus 74 when an import kept the replaced tree or a forget could not verify the removal, and 66 for an unreadable or incomplete source directory. Neither has been run against the installed provider.

Since B-06 S15 (source only) `--import-identity` is replaced by `--import ABSOLUTE_PRIVATE_AEGIS_DIR [--remove-source]` (operands in either order; an unknown, repeated or `=`-valued flag, a second directory or a relative path is a usage error, exit 2). The host first admits the directory (`host_import::SourceTree`): canonical path with no symlink component, a 0700 directory owned by the caller holding only `bundle/` and `identity/` (each the caller's, no group/other bits), only import members and the Store's empty `.lock`, every file a regular single-link file of the caller within its cap, identity files without group/other bits, and a bridge sidecar naming its credential at `DIR/identity/bridge-credential`. It then sends one bounded request and compares the provider's committed manifest with every sent path, and every sent length and digest except the bridge sidecar's (the provider rewrites its `credential_file`, so only its presence is checked). Only an exact match, and only with `--remove-source`, removes the directory, and only after re-checking that every inode, entry and digest is still what was sent. It prints one `import_result=` line of codes, counts and booleans (never a path, digest or file byte). Exit 0 committed (and removed when asked); 66 source refused, nothing sent; 65 provider refused before its commit; 69 the request cannot have reached the provider; 73 committed but the source was not (completely) removed; 74 committed but the provider kept its replaced tree; 75 no reply within 10 s; 76 manifest mismatch (source kept); 77 delivered but commit state unknown (interrupted connection, undecodable reply, or a refusal made after the commit). 75 and 77 print `import_result=unknown manifest_match=unknown`, source kept. `--forget-identity` is unchanged. Neither has been run against the installed provider.

Since B-06 S16a (source only) no profile verb reads a host-side `Aegis/` tree, which the host no longer has after S14. `--save-profile`, `--connect` and `--repair-runtime` first ask the provider for `profile-terms` (one bounded XPC exchange, at most 10 s and spent from the verb's single 30 s budget, before any preference call): the held tree's signed numeric relay endpoint, `macos_packet` DNS list and MTU, and the public bundle digest. The operator's `RELAY_IP` must equal the held relay host (else `profile_relay_mismatch`, exit 2); DNS and MTU are the provider's, never a host default. A refused or unanswered query exits with the `--ping` codes (65, 69, 75) and touches no preference; `--save-profile` then prints `owner_generation=G saved=false`. The four-argument `--disconnect` and `--status` make no provider query, so a stop or status read never depends on provider XPC (an older provider without the verb, a peer refusal, a timeout) or on held-tree health (after `--forget-identity`): they act on the one saved profile of this provider whose typed saved intent (`saved_provider_intent`) names exactly `OWNER_GENERATION` and `RELAY_IP`, completed with that profile's own saved DNS and MTU and held to every exact-intent check (`OwnedTarget::Saved`; a saved-intent target never admits connect or repair). Their success line has no `profile_sha256=`. The owner generation is still host-minted (an NSUUID): nothing in the held tree names one. The saved manager keeps includeAllNetworks, no exclusions, no enforceRoutes, on-demand off and the same five-key `providerConfiguration` the provider's `saved_provider_intent` parses; the save success line adds `profile_sha256=`. Bare `--profile-terms` prints the terms as one JSON line. `--list` lines are produced by `host_lifecycle::ProfileLine` (owner generation and scutil service id, an NSUUID, or `unavailable`) and parse back exactly.

Since B-06 S16d (source only, not yet run installed) `--save-profile PROVIDER_ID RELAY_IP --replace-existing` (the flag at most once, anywhere among the operands, and accepted by no other verb) modifies the one existing saved profile of this provider instead of refusing it: `manager::save_target` admits exactly one profile of this provider whose connection is Disconnected or Invalid (more than one is `multiple_provider_profiles_refused`, a non-idle one `existing_profile_not_idle`, both known-unsaved), and `manager::apply_intent` writes a fresh full-wide protocol (every flag set on a new object, the five-key `providerConfiguration` set before it is attached), the AEGIS description, enabled and on-demand off onto that loaded manager with a fresh owner generation, then saves, reloads and verifies. Zero existing profiles is a plain create; without the flag an existing profile still refuses with `existing_provider_profile_refused`. The required product shape is unchanged (includeAllNetworks, no exclusions, no enforceRoutes; `provider_shape_matches` is not relaxed). After every save's reload, `manager::verify_reloaded` checks the six flags first: a mismatch is `profile_flags_not_persisted` (`saved=unknown`), and every failure `verify_reloaded` finds after a reload that returned no error (`manager::SaveFailure::reloaded_line`) adds one stderr line `reloaded_profile owner_generation=G include_all=… exclude_local=… exclude_apns=… exclude_cellular=… exclude_device=… enforce_routes=…`, or `reloaded_profile owner_generation=G flags=unavailable` when the reload returned no provider protocol (`saved_profile_protocol_missing`) (`host_lifecycle::reloaded_flags_line`, the same flag text as `--list`'s `profile_diag`), so the next installed run shows whether macOS drops them. A reload error is now `profile_reload_failed` and, like a refusal before the save or a save error, prints no `reloaded_profile` line. A successful replace adds the stderr line `owner_generation=G replaced_existing_profile`; the stdout line is unchanged.

Since B-06 S21 (source only, not yet run installed) `--deactivate [dev.aegis.macos.PacketTunnel]` submits one `OSSystemExtensionRequest` deactivation request for this provider only (any other operand is a usage error, exit 2), shares the activation delegate, stops its run loop on the finish or failure callback, gives up after 120 s and prints one `deactivation_result=` line (`completed`, `will_complete_after_reboot`, `failed` with `error_domain`/`error_code`, `cancelled`, `not_found`, `timeout_awaiting_approval`, `timeout`; plus `will_complete_after_reboot` and `needs_user_approval`). Exit 0 completed, 20 completes after reboot (the extension keeps running until then), 21 failed (including an unknown result value), 22 cancelled, 23 `OSSystemExtensionErrorExtensionNotFound` (never treated as deactivated), 24 timeout while approval was pending, 25 timeout, 2 usage; every non-zero code differs from each activation and XPC code (`host_lifecycle::DeactivationTracker`). `packaging/uninstall-app.sh` is its only scripted caller.

Since B-06 S23 (source only) bare `--cert-status` prints the provider's certificate renewal state as one JSON line and bare `--renew` asks the provider to renew a due certificate now (identity-verb peer check and, since the security audit, the administrator prompt below); both use the `--ping` exit codes.

Since B-06 S20b (source only, not yet run installed) the host also accepts bare `--enable-filter`, `--filter-status`, `--disable-filter` and `--remove-filter` (`filter_manager.rs`; outcomes in `host_lifecycle::FilterOutcome`). Any operand is `filter_operand_refused`, exit 2. `--enable-filter` saves the reviewed leak-guard packet-filter configuration (packets only, packet provider `dev.aegis.macos.PacketTunnel`, description "AEGIS leak guard", enabled), reloads it and checks every field, bounded at 120 s for the user's answer to "would like to filter network content"; `--disable-filter` keeps the configuration with enabled=false, `--remove-filter` removes it and verifies none remains, and `--filter-status` reads it and, only when it is exact and enabled, asks the provider's `filter-status` (one XPC exchange, at most 10 s); these three are bounded at 30 s. Each prints one `filter_result=NAME exit_code=N` line. `--filter-status` adds the configuration fields and `attached=` (`unknown` when the provider was not asked, `refused`, `unavailable`); when the provider answers it adds `pid_match= mode= armed_token= dropped= allowed=` (`dropped=` and `allowed=` are the sums of the `drop_*` and `allow_*` counters) and prints the provider's JSON `filter-status` reply, with every per-reason counter (and the non-verdict `torn_snapshot`) and no address, as a second line. Exit 0 `ok`, 30 `not_configured` (removed or never saved), 31 `disabled`, 32 `field_mismatch`, 33 `not_attached` (enabled, but the provider reports the filter not attached in its process, or refused), 34 `failed`, 35 `permission_denied` (the Allow was declined), 36 `timeout`, 37 `removal_incomplete`, 67 `authorization_refused` (v26: `--disable-filter` or `--remove-filter` without an administrator's approval; nothing was changed), 69 `provider_unavailable` (enabled, no XPC reply), 2 usage. A disabled or removed filter never gives 33 or 69: the provider is not asked.

Since the B-06 security audit (v26, source only, not yet run installed) `--import`, `--forget-identity` and `--renew` first ask for an administrator at the system prompt (name and password, or Touch ID; every run prompts again), bounded at 120 s, and send the provider a one-use `AuthorizationExternalForm` for `dev.aegis.macos.identity-import` that the provider checks without interaction; `--disable-filter` and `--remove-filter`, which weaken the leak guard, ask the same way under their own right `dev.aegis.macos.leak-guard-weaken`, which the host itself checks, before NEFilterManager is touched and before their 30 s bound starts. Reading and enabling the filter never prompt. Each writes the banner `administrator approval required for this identity change; ...` (or `... for this leak-guard change; ...`) on stderr first. Without an approval (cancelled, denied, unanswered in 120 s, or a rule weaker than the one AEGIS registers) the host exits 67 having sent or changed nothing: `--import` prints its not-sent line, the filter verbs `filter_result=authorization_refused exit_code=67 filter_changed=false`, and the code (`identity_authorization_*` or `filter_authorization_*`) goes to stderr.

Since v39 (source only, not yet installed or run) `host.rs` started by LaunchServices with no verb (no arguments, or one `-psn_` serial, and stdin not a terminal: `menu_model::launched_as_app`) loads AppKit at run time and becomes the menu-bar app (`host/menu_app.rs`, minimal AppKit bindings in `host/appkit.rs` written with objc2's own `extern_class!`/`extern_methods!`, no new crate). The app runs each action as a child of this executable with one existing verb (`menu_flow::HostVerb`, whose arguments the tests bind to `parse_host_args`), on one worker thread, one at a time, bounded from outside past each verb's own watchdog. Every other start is unchanged, including a terminal start without arguments (usage, exit 2); CLI verbs never load AppKit, and the provider never links it. The assembler marks the app `LSUIElement` (no Dock icon). See the [user guide](../../../../../docs/platforms/macos/user-guide.md) and [known limits](../../../../../docs/platforms/macos/known-limits.md#menu-bar-app-v39-source-only).

Since B-06 S21j (v30, source only, not yet built or installed) the identity verbs' prompt is password only (no Touch ID) under the new right `dev.aegis.macos.identity-change`, names the change (`IdentityChange`: forget, import with the source folder's plain name, renew) and is followed, on the same reference and without interaction, by Apple's `system.services.systemconfiguration.network`, the right the provider's sandbox lets it re-check; only then is the one-use form sent under the XPC key `identity-approval` (an `IdentityApproval` exists only after both, and the host's identity queries take it by value). On v26 to v29 the provider's re-check of `dev.aegis.macos.identity-import` was always refused by its sandbox. New exit-67 codes: `identity_authorization_proof_rule_unexpected` (Apple's rule differs from the pinned shape; no prompt) and `identity_authorization_unprovable` (approved but not provable; nothing sent). `--disable-filter` and `--remove-filter` use the password-only right `dev.aegis.macos.leak-guard-change`. Bare `--identity-gate` asks the provider, read-only and with no prompt, whether an identity verb could be admitted now: the JSON reply, then `identity_gate=open|closed peer= identity_rule= proof_rule= proof_probe=`; exit 0 open, 65 closed (`identity_gate_closed <check>` on stderr) or refused (an older provider answers `unknown_verb`), 69 unavailable.
