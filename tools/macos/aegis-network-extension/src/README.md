# NetworkExtension Rust modules

`apple.rs` owns the native provider class and packetFlow callbacks; `configuration.rs` builds dual-family policy; `manager.rs` owns saved-profile operations, including the S11 list, removal and emergency stop over every profile of this provider; `host_lifecycle.rs` holds the host verb parser, the versioned replacement rule and the bounded activation outcome. `bridge.rs` bounds packet queues, `engine.rs` owns worker cancellation and joins, and `policy.rs` prevents stale completion from reopening a stopped owner. With the opt-in `client-engine` feature, `packet_engine.rs` connects those queues to the real shared Aegis packet engine and retains terminal errors across repeated joins. It is a mechanics adapter, not a provider factory or relay credential authority.

The containing app and system-extension entrypoints are in [bin](bin/README.md). Build commands, executed checks and unresolved relay/credential integration are documented in the [package guide](../README.md). Queue admission is not authenticated relay delivery or installed leak acceptance.

`app_group.rs` adds capture-only current-code/NE-entitlement/container observations and held native directory/private-file generation admission. Current source checks the exact provider code and Team-prefixed application identifiers with the system-extension Packet Tunnel entitlement; it does not approve the signing Team or release, or mint authenticated engine/PKI/lease/ACK authority. Its two executed native FD regressions cover real temporary files, generation mutation on callback error, hardlinks, FIFO, symlink and replacement refusal. Distinct R2 local macOS checks passed all 11 library methods, including the new role predicate, and strict library/test Clippy. Actual signed Security.framework AppGroup admission and profile permission remain untested, and the provider factory stays absent.

`runtime_binding.rs` (B-06 S03 part 4) derives the provider's runtime binding from the saved manager intent, the held signed bundle terms (`BoundRelayPolicy::signed_runtime_terms`, pinned relay, `macos_packet` DNS/MTU, public digest), the held profile digest and the held Store issuance; the provider never reads `runtime.json`. `render_for_host` keeps the host-only document. See the [package guide](../README.md).

`provider_xpc.rs` (B-06 S10) is the host<->provider diagnostics channel over hand-written libxpc FFI. The provider creates one listener on its `NEMachServiceName` (`group.TEAMID0000.dev.aegis.macos.packet-tunnel`) after `NEProvider::startSystemExtensionMode` and before the run loop; each new peer gets `xpc_connection_set_peer_code_signing_requirement` with the containing app's Developer ID requirement before it is resumed, so every verb is covered. The host connects with `XPC_CONNECTION_MACH_SERVICE_PRIVILEGED` and pins the provider's Developer ID requirement the same way. Frames are one bounded `frame` data value carrying canonical JSON; unknown verbs, oversized frames and non-canonical requests are refused. The only verbs are `ping` (euid, sandbox state, raw container URL and realpath, per-component custody errno from `/`, the S13 capture gates: each ancestor's lstat errno and owner/mode verdict, the container anchor open errno, whether its F_GETPATH matched and whether the container passes owner/mode admission, a 127.0.0.1 listen probe, session phase, identity presence below the matched anchor) and `status` (session phase and first refusal code). Both report the newest start attempt: a session's phase record is retained after the session is joined and dropped, without retaining the session, its bridge or its Store claim, so a failed session reads `sealed`/`joined` with its code; a start refused before any session existed reads phase `none` with that code. Neither is a relay ACK, packet permit or installed acceptance; connectivity is proven only in the attended installed run (S12).

`identity_import.rs` (B-06 S14) carries the `import` and `forget-identity` verbs of `provider_xpc.rs`: the fixed member table and caps, the versioned canonical manifest, the console-user and admin-group peer check (`SCDynamicStoreCopyConsoleUser`, `mbr_check_membership`), the provider tree gate that `CapturedAppGroupInputs::capture_claim` leases, and the commit: a 0700 staging directory in the held container, the production validators (`BoundRelayPolicy::from_snapshot`, `ProtectedOnlineExpectation::open_existing` + `expectation_at`), one `renameatx_np` of the whole `Aegis` tree and a manifest read back from the committed inodes. See the [package guide](../README.md).

`identity_custody.rs` (B-06 S22) checks the provider capture's held identity bytes. The held CSR must be `csr_for_key(record.device_id, held key)`, and the held completion receipt must bind the record, CSR, public profile digest and `device.pem` bytes. The Store's returned expectation must be exactly that receipt's issuance. `app_group.rs` holds `device.csr` and `online-completed.json` and refuses a pending online journal; import requires and checks the same receipt. See the [package guide](../README.md).

`host_import.rs` (B-06 S15) is the host side of `--import`: `SourceTree` admits one private, link-free source directory and reads it through held descriptors into the S14 payload; `conclude_import` re-checks the provider's committed manifest against every sent path and every sent length and digest except the provider-rewritten bridge sidecar's (presence only), classifies a delivered exchange that does not say whether the provider committed as `unknown` (exit 77), and alone decides whether `--remove-source` may remove the source, which it does only when the tree is unchanged since it was sent. Its tests drive the real provider envelope parser (`provider_xpc::respond_entries`) and S14 commit in process; the ignored `write_installed_fixture` writes the installed-run import source. See the [package guide](../README.md).

`profile_terms.rs` (B-06 S16a) answers the read-only `profile-terms` XPC verb from a fresh provider capture (`BoundRelayPolicy::capture`, signed runtime terms): numeric relay endpoint, DNS list, MTU and public bundle digest only, never key material, a certificate or a path, and no Store open. `host_policy` admits a reply for the host's profile verbs and refuses a relay that differs from the operator's `RELAY_IP`. See the [package guide](../README.md).

`menu_model.rs`, `menu_flow.rs` and `menu_diagnostics.rs` (v39, source only) are the menu-bar app's tested core; its AppKit glue is in [bin](bin/README.md). `menu_model` reads what the host verbs and `systemextensionsctl list` print (through the host's own `ProfileLine::parse` and `provider_xpc::decode_reply`) and derives the one state the menu shows (Checking, Move to Applications, Needs approval in System Settings, the four setup steps, Update ready, Disconnected, Connecting, Connected, Disconnecting, Blocked by leak guard, Certificate expired or renewing, Network extension not responding) and the actions it enables. `menu_flow` runs only existing CLI verbs as children (`HostVerb`, no weakening verb exists in it): read-only refresh, connect (leak guard ok first, the held relay from `--profile-terms`, the one profile saved or rewritten when stale), disconnect (exact intent, else `--emergency-stop`), activation, filter enable, import and the VPN step. `menu_diagnostics` builds the "Copy Diagnostics" report from allow-listed fields and masks it (IP addresses to their first label, user names in paths, UUIDs, long hex and base64-like runs, e-mail, PEM, secret-looking values).

`carrier_pool.rs`, `carrier_failover.rs` and `carrier_network.rs` (v40, CP-D3 M1 with the macOS side of D1/D2) replace the single held peer with the signed profile's ordered carrier pool. `carrier_pool` admits a v4 pool of 1 to 16 numeric pins (primary first, no repeats, no endpoint bandit, Geneva or paired shaping) and preloads one held outer connector per pin from the held CA bytes, each with that pin's TLS name and no pool policy; an ECH rejection with authenticated retry configs that keep the pinned public name rebuilds the connectors of that name so the dial redials once, and a refused redial forgets the rotation (fail closed). `carrier_failover` keeps one aegis-core `CarrierFailover` per profile in the provider process (RAM only), plans each session build's pin order, and maps the provider's own observations to its signals: a TCP dial refused or timed out, an outer handshake cut, no outer carrier in time and a non-200 carrier answer before any identity move the build to the next pin (`provider_session_body::first_carrier`); a session that opened records `Opened`, a pooled connection its stall watchdog closed records a freeze, a slow PONG a collapse, a lease that ran out without a wake or re-pin a freeze, and two pre-authentication failures of its later dials end it as `carrier_unavailable` for a rebuild. `carrier_network` derives the access network key from a process-wide Network.framework path monitor (physical interface type and name and the path's gateways, hashed with a per-process salt). The leak guard arms the whole pool, every exact pin and nothing else (`leak_guard::PeerSet`), so a rebuild on another pin needs no re-arm and a fronted authority on an edge pin's 443 (variant B) renews through the relay route. See the [package guide](../README.md).
